不把「检索到」当成「可以答」。

2027 届计算机科学与技术本科。三个开源项目都在回答同一个问题： 当模型不确定时，Agent 该怎么决策 —— 用检索置信度做路由信号， 决定「直答 / 走工具循环 / 拒答转人工」，而不是让大模型对所有问题都说点什么。

1核心方法：把置信度变成决策

这套路由贯穿了下面三个项目。它不是"调了个阈值"，而是把检索分数从"参考信息"提升为"控制流信号"。

关键取舍：高置信不等于应当直答。 知识库里有答案，不代表用户问的这件事只需要知识库 —— 「昨晚这台机器为什么变慢」可能既命中知识条目、又必须去查真实日志。所以路由是双向的：相似度决定"够不够像"，覆盖率和意图规则负责"该不该去查"。

第二层：编排引擎不是不可替换的。 每个项目的 ReAct 主循环都有一份手写实现和一份 LangGraph 图编排实现，同签名、同事件协议，用固定剧本做逐步等价性对照 —— 这样"换框架"变成一次可验证的重构，而不是黑盒迁移。

2三个开源作品

依次是：运维场景的原始实现 → 迁移到银行坐席（同构换皮）→ 换到完全不同的领域（内容监控）。第三个刻意不复用前两个的骨架，用来证明这套方法不是只能套在一种业务上。

银行远程坐席知识助手

bank-agent
已开源 · MIT

面向银行远程银行坐席的问答 Agent。核心是把「检索到就作答」改成按置信度决定作答方式，并对资金安全类问题做强制工具升级。

179断言 / 5 个测试套件
  • 三基线对照：同一条链路只换"谁来答"，纯 RAG 与本地小模型失败的是同样 7 道题，全是「答案不在知识库里」→ 结论落在知识边界与编排层，而不是模型大小。
  • 消融实验：同模型、同检索、同提示，唯一差别是不挂 adapter —— 59.5% → 66.7%，修好 3 道、弄差 0 道。证明 LoRA 学到的是"按坐席口径完整作答"这个行为。
  • 防泄漏：训练集与评估集做两道闸门（精确 + 相似度 ≥0.72 剔除），第一版只做精确剔除时剔了 0 条、看着干净，实际藏着 8 条近重复。
  • 主动约束：资金安全类问题不走概率路由，强制升级人工；工具白名单 + JSON 解析兜底 + 执行异常捕获三层防御链。

  • 三级路由：sim≥0.70 且关键词覆盖率≥0.30 → RAG 直答；0.45≤sim<0.70 → Agent 循环；sim<0.45 → 拒答转人工。

xhs_monitor
已开源

换到完全不同的领域：定时监控公开笔记与作者主页，做增量判断、规则 + LLM 混合分析、告警去重与风险自适应调度。这个项目的重点是工程约束下的诚实。

风险状态机增量抓取 规则 + LLM 混合Provider 抽象 PostgreSQL / AlembicDocker
17单元测试通过
3评测基线对照
120s全局最小请求间隔
100%意图任务漏接率（发现的问题）
  • 执行流是确定性的：规则规划器 → 风控门控 → 采集 → ETag / 内容哈希增量 → 混合识别 → 路由 → 告警。LLM 不控制抓取循环，只理解"已经发生变化的公开内容"。
  • 风险控制落到参数：全局 120 秒最小间隔、周期 ±20% 抖动、跳过凌晨低收益时段、来源日预算、429 遵守 Retry-After、403 与验证码进 24 小时冷却、连续三次异常熔断。
  • 用评测发现自己代码的错：固定标注集上跑三基线，结论是现有分析器在"评论购买意向"任务上漏接率 100% —— 因为它会把非负面的高相关内容主动降级。这是评测暴露出的真实缺陷，已定位到具体函数。

5诚实边界

把"没做到什么"写在明处，比让面试官自己发现要划算。

这些是演示原型，不是生产系统

  • 数据是构造的：银行项目的知识库与工单由脚本生成；运维项目的日志与监控指标由脚本确定性重建。刻意不用任何真实客户数据。
  • 没有真实用户量验证：所有评测都是固定测试集上的可复现结果，不代表线上表现。
  • 内容监控项目主动关闭了一个能力：因为没有官方授权数据源，站内关键词全网发现明确置为 disabled，并在界面上主动声明。同时明确不做代理轮换、签名伪造、账号池或验证码绕过。
  • 银行项目是运维项目的同构换皮：这件事写在它的 README 里。它证明的是方法可迁移，不是两个从零开始的独立项目。
  • 还没做的：真实业务系统对接、线上监控与灰度、多轮长对话的记忆压缩。
